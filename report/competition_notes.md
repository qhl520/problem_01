# 赛题说明整理

## 1. 赛题目标

天池“资金流入流出预测”赛题要求根据历史用户资金行为，预测 2014 年 9 月每一天的资金申购总额和赎回总额。预测对象是每日总量，不是单个用户行为。

预测区间：

```text
2014-09-01 到 2014-09-30
```

目标字段：

- `purchase`: 每日申购总额
- `redeem`: 每日赎回总额

金额单位为分，即 `0.01` 元人民币。

## 2. 数据文件说明

比赛数据主要包含四个部分：

| 文件 | 含义 |
| --- | --- |
| `user_profile_table.csv` | 用户基本信息数据 |
| `user_balance_table.csv` | 用户申购赎回数据 |
| `mfd_day_share_interest.csv` | 余额宝收益率表 |
| `mfd_bank_shibor.csv` | 上海银行间同业拆放利率 Shibor 表 |

提交样例或最终结果表为：

```text
tc_comp_predict_table
```

## 4. 收益计算方式

赛题基于实际余额宝收益方式做了简化：

- 收益计算时间使用自然日，以 0 点为分隔。
- 0 点之前转入或转出的金额算作昨天。
- 0 点以后转入或转出的金额算作今天。
- 收益首次显示时间按转入星期决定。

简化后的首次显示收益时间：

| 转入时间 | 首次显示收益时间 |
| --- | --- |
| 周一 | 周三 |
| 周二 | 周四 |
| 周三 | 周五 |
| 周四 | 周六 |
| 周五 | 下周二 |
| 周六 | 下周三 |
| 周日 | 下周三 |

该规则解释了 `share_amt` 的时滞特征，因此建模时收益率和收益相关字段不能直接使用未来值。

## 5. 提交格式

提交结果表为 `tc_comp_predict_table`，字段如下：

| 字段 | 类型 | 含义 | 示例 |
| --- | --- | --- | --- |
| `report_date` | bigint | 日期 | 20140901 |
| `purchase` | bigint | 申购总额 | 40000000 |
| `redeem` | bigint | 赎回总额 | 30000000 |

提交要求：

- 2014 年 9 月每天一行；
- 共 30 行；
- 与选手结果数据样例文件一致，不包含表头；
- 字段之间以逗号分隔；
- `purchase` 和 `redeem` 均为金额数据，精确到分；
- 日期必须覆盖 20140901 到 20140930。

## 6. 评价指标

评价指标希望未来 30 天每一天的申购和赎回总量预测尽量准确。官方使用积分式评分方法：

1. 计算每天申购和赎回总额的相对误差；
2. 将相对误差映射为每日得分；
3. 当误差为 0 时，当天得分为 10；
4. 当相对误差大于 0.3 时，当天得分为 0；
5. 误差到得分的完整映射函数不公布，但保证单调递减；
6. 总积分按业务权重加权：

```text
总分 = 申购预测得分 * 45% + 赎回预测得分 * 55%
```

本项目的 `src/evaluate.py` 使用线性近似函数复刻该约束，仅用于本地模型对比，不代表线上真实得分。

## 7. 时间范围

- 训练历史：2013-07-01 至 2014-08-31；
- 预测测试期：2014-09-01 至 2014-09-30。

## 8. 建模注意事项

- 不能随机划分训练集和验证集。
- 必须使用时间序列验证。
- 不能使用 2014 年 9 月真实值。
- lag 和 rolling 特征只能来自历史数据。
- rolling 特征必须先 `shift(1)`。
- 金融利率和收益率特征只能使用历史 lag 版本。
- 预测 2014 年 9 月时必须逐日递归。
- `purchase` 和 `redeem` 分别建模或分别融合。

## 9. 可能的数据泄露风险

- 使用测试期真实目标。
- 使用验证月真实目标生成 lag 或 rolling。
- rolling 特征未先 `shift(1)`。
- 将 `purchase`、`redeem` 或 `date` 直接作为模型特征。
- 使用未来收益率或未来 Shibor 利率。
- 使用测试期新增用户的真实行为统计。
